# PT-SEM JMLR final reproducibility snapshot (2026-07-21)

This directory is an isolated, copy-based snapshot of the programs and saved
results that produce the current paper Figures 1-6, plus the JMLR All-Poisson
extension. Original project code and results were not edited, moved, renamed,
or deleted. The project root is not a Git repository; see `SOURCE_STATE.txt`.

## Quick commands

Run from this snapshot directory. No source path needs to be edited.

```bash
bash scripts/run_reproduction.sh --verify-existing
bash scripts/run_reproduction.sh --run-all-poisson-missing
bash scripts/run_reproduction.sh --summarize
bash scripts/run_reproduction.sh --plot-figure4
bash scripts/run_reproduction.sh --all
```

The default is 12 workers. Override without editing code:

```bash
PTSEM_WORKERS=8 bash scripts/run_reproduction.sh --run-all-poisson-missing
```

On PowerShell, the corresponding direct entry points are:

```powershell
python scripts/verify_existing_figures.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_all_poisson_overnight.ps1 -Workers 12
python scripts/summarize_all_poisson.py
python scripts/plot_all_poisson_final.py
```

The overnight wrapper runs the formal preflight before any full cell, requests
Windows to block idle system sleep while it is active, records a transcript,
and releases the request in a `finally` block. The monitor may turn off. Keep
the machine connected to AC power and do not close a laptop lid, manually put
Windows to sleep, or allow a scheduled reboot. Re-running the same command is
safe because complete replications are retained from atomic checkpoints.

## Formal six-family simulation design (Figures 1-3)

The frozen formal runner is
`frozen_code/simulation/ptsem_six_family_final_suite.py`; its estimator and DGP
core is `frozen_code/methods/d.py`. The recorded run is
`six_family_final_v1`, master seed `20260622`, `R=100`, `max_parents=5`, and
`generation_mode=exact_edges`. It uses fixed node-index topological order,
randomizes the eligible-edge permutation, and selects exactly
`round(d * average_indegree)` edges. Data seeds use NumPy `SeedSequence` over
`[base_seed, d, replication, stream]`. All methods in one replication receive
copies of the same data.

The sweeps are dimension 4-10 at `N=3200`, sample size
100, 200, 400, 800, 1600, 2400, 3200, 6400, 10000 at `d=8`, and average
indegree 1.0-3.0 at `d=8, N=3200`. Restricted coefficients are Uniform(0.15,
0.85); extended coefficients are Uniform(0.2, 2.0). PB-SCM and PB-SCM-PGF are
excluded from extended.

Note: this section describes the historical source snapshot exactly as
recovered, including its `N=2400` sample-size cell. That cell was later
confirmed by the author to be a leftover artifact from an abandoned prior
experiment revision, not part of the manuscript's intended grid, and has been
removed from the repository's committed data/summaries/figures. See
`docs/UNRESOLVED_PROVENANCE.md` for the correction record; this historical
description is left unmodified as provenance evidence of the original find.

## New All-Poisson extension

The exact design is frozen in
`frozen_configs/all_poisson/jmlr_all_poisson_formal_design_v2.json`. The runner
imports the frozen formal `d.py` at its snapshot path and calls the unchanged
`d.run_experiment` / `d.simulate_ptsem` framework. The only DGP specialization
replaces `d.make_exogenous_specs` with Poisson at every node and iid
`lambda ~ Uniform(2,10)`; the frozen code and author baselines are not edited.
It adds dimension, sample-size, and average-in-degree sweeps for both regimes.
The restricted row uses Proposed DP-BIC, Greedy-BIC, Poisson-only DP, ODS,
PC-RCIT, PB-SCM, and PB-SCM-PGF. The extended row uses only the first five
methods. The formal internal `OracleDP` path is displayed as Poisson-only DP:
preflight verifies every admissible local score equals a direct Poisson-only
restriction, so no duplicate Oracle curve is run or plotted.

Each sweep value receives a stable cell base seed from the first 63 bits of
SHA256 over `master_seed|all_poisson|sweep|canonical_value`. Restricted and
extended share that base seed deliberately for paired designs. Dataset and
method seeds then use the frozen formal NumPy `SeedSequence` rule over
`[cell_base_seed,d,replication,stream]`. The reused restricted sample-size cells
retain their historical SHA256 seed. The complete 4,000-row table is stored in
`new_results/all_poisson/metadata/seeds.csv`; Python `hash()` is never used.

## Raw result and log schema

Each formal cell is stored at:

```text
new_results/all_poisson/formal_cells/<regime>/<sweep>/value_<value>/experiment1_raw_results.csv
new_results/all_poisson/logs/formal_cells/<regime>/<sweep>/value_<value>.json
```

The formal runner atomically rewrites the cell CSV after every completed
replication. It retains only replications containing exactly one row for every
required method; incomplete replications are deterministically recomputed on
resume. Raw rows include data and method seeds, true Poisson parameters, true
alpha matrix, true and estimated edge sets, runtime, directed F1, skeleton F1,
exact recovery, and selected family information. Cell JSON records start/end,
status, exception, runtime, exact config, output path, and strict validation.

The consolidated raw CSV is
`new_results/all_poisson/raw/all_poisson_per_replication.csv`. The summary is
`new_results/all_poisson/summaries/all_poisson_summary.csv`. Confidence
intervals are pointwise Monte Carlo intervals for the mean:
`mean +/- 1.96 * SD(ddof=1)/sqrt(R_success)`.

## Validation gates

`scripts/summarize_all_poisson.py` refuses a final plot unless every
method/setting cell has exactly 100 successful replications, with no duplicate
raw keys, duplicate data seeds, failed rows, NaN F1 values, coefficient-range
violations, non-Poisson exogenous labels, shared-data violations, PB-SCM rows in
extended, or directed-edge F1 mismatches. It also checks the reused sample-size
summary against the original Figure 4 plotdata and records the large-sample
trend of Proposed DP-BIC and Poisson-only DP.

## Runtime and environment

The new 3,200 dataset jobs are CPU-heavy. Runtime depends strongly on dimension
and baseline behavior and may exceed one night; no shorter completion claim is
made. With 12 workers, interrupted work resumes from replication checkpoints.
Plot-only and verification commands take under a minute. The exact current
Python environment is in `environment/`; conda was
not installed, so `conda_environment.yml` explicitly records that condition.
The host also did not expose `bash` on `PATH`; the required shell entry point
is included and portable, while the listed direct PowerShell commands are the
tested entry points on this machine.
The original formal run's package versions remain in the copied suite
manifest and may differ from the current plotting/execution environment.

## Known limitations

- The project root has no Git metadata, so no commit/branch/diff can be
  recovered. This is recorded rather than guessed.
- Reused legacy sample-size rows contain runtime and status but did not record
  per-method UTC start/end timestamps; those fields are blank in the normalized
  reused CSV. The original overnight log is frozen.
- Current environment NumPy differs from the original formal suite manifest;
  both versions are recorded. The current NumPy 2 environment supplies the
  documented replacement for removed `np.asfarray`, required only by pinned
  KDEpy 1.1.4 in PB-SCM; formal and author sources remain unchanged. The
  seven-method preflight must pass before every full launch.
- The discarded custom-generator run (437 replications) is preserved only at
  `new_results/all_poisson/quarantine/20260722_unverified_custom_generator/`.
  Active formal scripts do not read any quarantine path.
- `bash` was not installed/on `PATH` on the snapshot host; use the documented
  direct PowerShell commands there, or the shell entry point in Git Bash/WSL.
- The snapshot validates the current `final_paper_figures/` set. Legacy upload
  directories are preserved in place and are not silently overwritten.
